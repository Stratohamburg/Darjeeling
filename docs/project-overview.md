# Darjeeling 项目大纲

Darjeeling 是一个侧视台阶地形上的建造与物流经营原型。玩家在有限的实体地面上规划建筑、改善道路，主动把人力分配到工作地点或点对点运输线，观察高度差与移动能力如何影响布局。React 管理控件，PixiJS 绘制场景；规则使用独立 TypeScript 领域模块，不依赖浏览器或渲染框架。状态暂存内存，刷新重置。

## 设计支柱

- 空间规则一致：建筑、道路、主体与线路共用整数 `(column, level)`，显示缩放不改变世界。
- 地形有意义：空洞、支撑、可行走性和固定高度差影响建造与通行。
- 视觉与占用分离：高建筑可以遮挡画面，但不会凭空占用其他台阶。
- 人力分配明确：一个工人只属于一个工作地点或一条运输线，等待不自动改派。
- 路线可解释：可见线路直接使用实际寻路边，阻塞有原因，恢复后可以重算。

## 世界与建筑

`column` 向右递增，`level` 向上递增；每个格子为正方形，相邻层级高度差 `stepHeight` 必须等于列宽 `cellWidth`，当前统一为 40 个逻辑像素。地面、空洞网格与占地高亮使用相同方格边界，视口沿两个方向等比缩放。每个位置独立保存 `air` 或实体地面，不能只用每列最高点表示世界。实体地面独立声明材质、`supportsBuilding` 和 `walkable`；不可支撑与不可行走是两个不同限制。空洞不能直接承载建筑、道路或移动主体。

普通建筑由锚点与横向宽度定义，在一个台阶上占连续格子，全部格子必须有实体支撑且没有互斥占用。候选位置不占地，确认后立即占地并施工，取消返回预览，Esc 分步退出。视觉高度、遮挡范围与深度顺序单独记录；遮挡只影响绘制与透明度。桥与平台必须显式声明跨层占地、支撑位置和通行连接，不能从视觉高度推导；本版提供模型扩展点，不加入桥平台目录。

## 道路与能力

可行走实体格默认有野路底边。相邻同层底边连续才形成水平路线。石板路、水泥路升级只改变类型与相对代价；移除底边会断路，恢复野路需要显式命令。野路攀爬连接同列相邻层，代价高；不能跳层。

楼梯占 1 个横向格，跨 1 层。斜坡占连续 2 或 3 格，跨 1 层；端点及内部地面必须有效。结构与建筑共用互斥占地；失败不产生部分占用或连接。多层高度差必须通过连续的结构完成。

| 主体 | 野路/石板/水泥水平段 | 野路攀爬 | 楼梯 | 斜坡 |
| --- | --- | --- | --- | --- |
| 人 | 可以 | 可以 | 可以 | 可以 |
| 牲畜 | 可以 | 可以 | 可以 | 可以 |
| 车辆 | 可以 | 不可以 | 不可以 | 可以 |

道路、攀爬、楼梯与斜坡代价集中配置，保持攀爬高于水平移动。具体数值是原型相对值，尚未确定最终平衡。确定性寻路先过滤能力再比较成本，返回完整逻辑边或不可达原因。通行版本变化会使旧路线需要重算，主体不能沿失效边继续移动。

## 工作与运输

工作地点（如田地、工坊）与仓储节点暴露位置、是否参与搬运、岗位容量和工作可用状态。容量是模型字段，演示岗位数不是最终产能设计。一个工人的分配为未分配、工作地点或运输线之一；重新分配先校验目标，成功后释放旧岗位。容量满或运输能力不兼容时保留原分配。

运输线只有一个起点与一个终点，端点必须是可搬运工作地点或仓储节点。系统自动按主体能力寻路。路线保存实际底边道路与攀爬/楼梯/斜坡引用；地图修改后进入需要重算或阻塞状态，有合法新路线时恢复。中途经过其他节点不产生停靠行为。

首版线路选择一种搬运主体（人、牲畜或车辆），岗位只接收该类型，确保线路覆盖与实际搬运路径使用相同能力。取货和交付只驱动可观察任务阶段；多站点、循环站序、货物容量和库存调度仍是后续能力，不从当前状态演示推导完整物流经济。

## 工人与移动状态的可视化契约

领域快照对每个主体暴露 `id/name/agent/position`、唯一 `assignment`、`task`、`reason`、`route`、`routeIndex` 与 `carrying`。界面从这些字段显示岗位、阶段、阻塞原因与地图位置，不从动画猜测状态。人用圆形，牲畜用椭圆和角，车辆用车体与轮子；携货用金色标记，等待/阻塞用红色标记。车辆的说明应直接提示只能走斜坡。

任务阶段为 `idle` 空闲、`going-to-work` 前往工作、`working` 工作中、`going-to-pickup` 前往取货、`picking-up` 取货、`carrying` 搬运、`delivering` 交付、`waiting` 等待。交付后沿同一通行规则空载返回起点，仍是一条单起点到单终点运输线，不增加隐式停靠点或循环站序。

阻塞原因为 `unreachable` 不可达、`invalid-endpoint` 无效地面、`route-invalidated` 需重算、`no-work` 暂时无任务、`target-missing` 岗位不存在、`line-blocked` 运输线阻塞。地图通行版本改变时先停止旧路线；重算命令保持分配和载货阶段，再从当前位置寻找新路。没有工作时保持原岗位等待。

## 术语表

| 术语 | 含义 |
| --- | --- |
| column / level | 横向整数格 / 向上增加的整数台阶 |
| air / ground | 空洞 / 实体地面；支撑与可行走性另外声明 |
| footprint | 逻辑占地，普通建筑为单层连续横向格 |
| visual / occlusion | 视觉体积 / 遮挡区域，均不增加占地 |
| bottom road | 格子底边道路段，wild / stone / concrete |
| traversal structure | 显式占地与端点的楼梯或斜坡 |
| capability | 主体可用的连接类型 |
| workplace / assignment | 工作地点 / 唯一主动岗位引用 |
| transport line / route | 点对点运输任务 / 引用实际道路结构的逻辑路径 |
| traversal version | 通行状态版本，用于识别需要重算的旧路线 |

## 当前原型与基础模型迁移

实施前可运行的是正俯视矩形建造原型：24 × 18 网格、矩形占地、确认与施工流程。`define-terraced-game-foundation` 已将运行原型迁移为 24 列、4 层的侧视基础模型；README 描述已实现的建造、岗位与运输操作。

迁移按文档 → 台阶地形与坐标 → 横向占地 → 道路寻路 → 工人与运输线 → PixiJS/React 适配 → 生产构建验收完成。确认、取消、Esc、独立施工计时、稳定快照和订阅清理继续有测试覆盖。

迁移核对：旧 `src/domain/grid.ts`、`layout.ts` 及其矩形专用测试已由 `world.ts`、`terraceLayout.ts`、`footprint.ts` 与相应测试替代；`types.ts`、`GameStore`、PixiJS 与 React 共用 `(column, level)`。运行代码已无旧 `row/col`、`cellSize`、`MapConfig` 或矩形 footprint 转换引用，领域层无 React/PixiJS 依赖。本轮没有需要保留的俯视兼容代码或待删除过渡点；旧 OpenSpec 原型变更保留为历史规划背景。后续功能应扩展现有台阶规则，避免在 UI 中另建坐标或占用解释。

## 后续路线与待定内容

- 资源种类、库存容量、配方、生产周期、岗位产能与经济数值：后续经济系统确定。
- 货物容量、库存调度、多站点、循环路线和货物优先级：独立后续能力；首版只演示取货、搬运、交付状态，不模拟库存账本。
- 地形改造与地图生成：是否允许填充 `air`、改造成本、专用建筑与程序化生成规则仍待定。
- 最终美术、动画、相机体验与遮挡特效继续迭代；存档、后端、账户和联网不在本版范围。
